# report-writing-style

一款面向国企正式报告的通用 AI 写作技能。它主要做两件事：

- 根据你提供的提纲、要点和参考材料，写出指定章节；
- 润色已有文字，减少“AI 味”，同时保留原有事实和结论。

它适合分析报告、可行性研究报告、立项报告、方案汇报和风险评估材料。

> 第一次使用只需记住一句话：在你的 AI 助手中启用本技能，并明确说“按本技能写作/润色”。

## 这个技能能做什么

使用后，AI 助手会尽量让文字做到：

- 先讲依据和事实，再下判断；
- 表达正式、稳健、克制，不堆砌口号；
- 把风险、影响和措施说具体；
- 删除“生态闭环”“全面赋能”等空泛表达；
- 不擅自编造政策、数据、合同内容或项目进展；
- 润色时不改变原文的事实、结论和判断强度。

它不会替你完成以下工作：

- 凭空设计整篇报告的目录和架构；
- 在没有材料时补造数据、政策或结论；
- 擅自扩写提纲之外的章节；
- 判断未经核实的事实究竟对不对。



## 两种常用方式

### 用法一：根据提纲和参考资料写作

提供提纲和参考资料即可：

```text
请启用 report-writing-style 技能，根据以下提纲和参考资料写作。

【提纲】
（粘贴提纲）

【参考资料】
（粘贴事实、数据、政策、合同内容或项目进展）
```

### 用法二：润色 AI 编写的初稿

提供 AI 已经写好的初稿即可：

```text
请启用 report-writing-style 技能，润色以下 AI 编写的初稿。

【初稿】
（粘贴 AI 初稿）
```


## 常见问题

### 1. 为什么它没有直接写完整篇报告？

这是技能的设计边界。它负责文字表达，不负责凭空设计整篇报告架构。请先提供提纲，并告诉它本次要写哪些章节。如果你使用了另一个负责报告架构的技能，可以让两个技能配合使用。

### 2. 为什么正文里出现了“需补充”？

说明你给出的材料不足以支撑相应判断。这是为了防止编造。补充事实、数据、政策依据或合同信息后，再让 AI 助手重写该处即可。

### 3. 为什么润色后有些句子没有变化？

该技能遵循“最小修改”原则。没有命中具体问题、且已经符合正式报告文风的句子会尽量保留。

### 4. 可以只说“去 AI 味”吗？

可以，但建议同时说明“不得改变事实和结论”。更稳妥的提示词是：

```text
请启用 report-writing-style 技能，去除下面文字的 AI 味，只改表达，不改变事实、数据、结论和判断强度。
```

### 5. 可以让它修改数字或结论吗？

不能依靠本技能直接修改。请先明确给出经过确认的新数字或新结论，再要求它据此重写。技能不会自行判断原数字是否正确。

### 6. 结果还是不符合我的习惯怎么办？

指出具体句子和你想要的方向，例如“这句话判断太满”“保留原来的长句节奏”“不要使用‘赋能’”。最好同时给出一小段你认可的示例，便于继续调整。

## 安装与文件

克隆本仓库后，将整个目录放入所用 Agent 的 skills 目录：

```powershell
git clone https://github.com/cwjcharles/report-writing-style.git
```

须同时保留 `SKILL.md` 和 `references/less-ai-tone-rules.md`，只复制入口文件会缺少通用规则。技能版本记录在 `SKILL.md` 的 `metadata.version`；规则来源及许可见[通用规则文件](references/less-ai-tone-rules.md)。
