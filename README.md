# report-writing-style

一款面向国企正式报告的 Codex 写作技能。它主要做两件事：

- 根据你提供的提纲、要点和参考材料，写出指定章节；
- 润色已有文字，减少“AI 味”，同时保留原有事实和结论。

它适合分析报告、可行性研究报告、立项报告、方案汇报和风险评估材料。

> 第一次使用只需记住一句话：把材料交给 Codex，并明确说“使用 `$report-writing-style` 写作/润色”。

## 这个技能能做什么

使用后，Codex 会尽量让文字做到：

- 先讲依据和事实，再下判断；
- 表达正式、稳健、克制，不堆砌口号；
- 把风险、影响和措施说具体；
- 删除“生态闭环”“全面赋能”等空泛表达；
- 不擅自编造政策、数据、合同内容或项目进展；
- 润色时不改变原文的事实、结论和判断强度。

它不会替你完成以下工作：

- 凭空设计整篇报告的目录和架构；
- 在没有材料时补造数据、政策或结论；
- 擅自扩写提纲之外的章节；
- 判断未经核实的事实究竟对不对。



## 两种常用方式

### 用法一：根据提纲写指定章节

可直接复制下面的模板：

```text
请使用 $report-writing-style 完成以下写作任务。

【报告类型】可行性研究报告
【本次只写】项目实施的必要性
【使用场合】提交公司内部决策会议审议
【字数要求】约 1000 字
【提纲】
1. 现有业务面临的问题
2. 项目实施的现实需要
3. 对公司能力建设的作用

【参考材料】
（在这里粘贴事实、数据、政策、合同内容或项目进展）

【特别要求】
1. 不生成提纲以外的章节；
2. 不得编造材料中没有的信息；
3. 缺少依据时直接标注“需补充”；
4. 交稿前按技能规则自检。
```

### 用法二：润色已有初稿

可直接复制下面的模板：

```text
请使用 $report-writing-style 润色下面的初稿。

【要求】
1. 只改表达，不改变事实、数据、结论和判断强度；
2. 删除空泛拔高、生硬造词和自媒体口语；
3. 保留必要的专业术语；
4. 输出修改后的完整文本；
5. 再列出主要的修改前后对照和简短理由。

【原文】
（在这里粘贴初稿）
```


## 常见问题

### 1. 为什么它没有直接写完整篇报告？

这是技能的设计边界。它负责文字表达，不负责凭空设计整篇报告架构。请先提供提纲，并告诉它本次要写哪些章节。如果你使用了另一个负责报告架构的技能，可以让两个技能配合使用。

### 2. 为什么正文里出现了“需补充”？

说明你给出的材料不足以支撑相应判断。这是为了防止编造。补充事实、数据、政策依据或合同信息后，再让 Codex 重写该处即可。

### 3. 为什么润色后有些句子没有变化？

该技能遵循“最小修改”原则。没有命中具体问题、且已经符合正式报告文风的句子会尽量保留。

### 4. 可以只说“去 AI 味”吗？

可以，但建议同时说明“不得改变事实和结论”。更稳妥的提示词是：

```text
请使用 $report-writing-style 去除下面文字的 AI 味，只改表达，不改变事实、数据、结论和判断强度。
```

### 5. 可以让它修改数字或结论吗？

不能依靠本技能直接修改。请先明确给出经过确认的新数字或新结论，再要求它据此重写。技能不会自行判断原数字是否正确。

### 6. 结果还是不符合我的习惯怎么办？

指出具体句子和你想要的方向，例如“这句话判断太满”“保留原来的长句节奏”“不要使用‘赋能’”。最好同时给出一小段你认可的示例，便于继续调整。
